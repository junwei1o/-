# 語義色階 Token 體系（Semantic Color Scale Tokens）

> 版本：2026-09-28 · 狀態：**提案（數值已全數驗算）**
> 目的：收斂全站 **~1200 處** 未 token 化色值，使「換主題」對全部元素生效，
> 並以自動閘門保障 WCAG 對比度。
> 前置閱讀：`docs/design-tokens.md`〈色碼收斂的實測結論〉。

---

## 0. 設計前提（三個硬約束）

這三點決定後面所有規則，都是**實測**得出而非理論假設：

| # | 約束 | 實測證據 | 對設計的影響 |
|---|---|---|---|
| **1** | **主題會改色相** | `--tidal`：default `#0B6E8E`→194.7°、`exlibris` `#4F6B52`→126.4°、`sunny` `#D0932B`→37.8° | 色階**不可寫死 hex**，必須執行期由基色派生 |
| **2** | **用 `--ink` 混合會變色相** | `danger` 基色 39.8° 用 64% ink 混合 → `#844C37`，褪成褐色 | 暗色步改用 **OKLCH + 黑色**，色相偏差 <2° |
| **3** | **黃色暗化必然變橄欖** | `warning` 黃色 85°，壓到 L=0.45 後視覺已是橄欖/褐色 | warning 暗色步**語義上是「深警告色」**，非「亮黃」 |

> 約束 2 是本次分析最重要的發現：`color-mix(in srgb, X, var(--ink))` 看似合理，
> 實際會把珊瑚紅、黃色、橙色全部拉向中性褐——**這正是舊設計失效的根因之一**。

## 1. 命名規範

```
--color-<category>-<step>
     └──語意類別        └──層級（50/100/200/…/900）
```

| 規則 | 說明 |
|---|---|
| 前綴固定 `--color-` | 與既有 `--radius-*`／`--type-*`／`--space-*` 同構 |
| 類別用**語意**不用色名 | ✅ `primary`／`success`；❌ `blue`／`green` |
| 層級固定 10 檔 | `50 100 200 300 400 500 600 700 800 900`，**不用中間值** |
| 同義詞只留一個 | 正式名 `danger`；`error` 不另立（避免兩套 token 需要同步） |
| 語意別名可存在 | `--color-danger-600` 是正式名；區塊級用途用別名指向它 |

### 層級的通用語意約定

| 層級 | 角色 | 前景 | 驗收 |
|---|---|---|---|
| **50–400** | **背景／填充**（淡底、hover 底、badge 底、圖表填充面） | 配 `neutral-900`（ink） | 白字**一律不達標**，禁做實體底 |
| **500** | **基準色**＝現有品牌 token 的精確值 | 見各表 | 舊 token 的等值替換點 |
| **600** | **預設實體色**（按鈕、連結、圖表主色） | **白字** | 四主題全 ≥6.0:1 |
| **700** | hover／強調 | 白字 | ≥7:1 |
| **800–900** | 大標文字、深壓 | 白字 | ≥10:1（AAA） |

## 2. 派生方式

色階分兩段，**兩段都不寫死 hex**：

```css
:root {
  /* ── 50–400：與 white 混合（僅作背景）── */
  --color-primary-50:  color-mix(in srgb, var(--tidal) 6%,  var(--white));
  --color-primary-100: color-mix(in srgb, var(--tidal) 15%, var(--white));
  --color-primary-200: color-mix(in srgb, var(--tidal) 30%, var(--white));
  --color-primary-300: color-mix(in srgb, var(--tidal) 50%, var(--white));
  --color-primary-400: color-mix(in srgb, var(--tidal) 72%, var(--white));

  /* ── 500：基準（＝舊品牌 token）── */
  --color-primary-500: var(--tidal);

  /* ── 600–900：OKLCH + 黑，保色相（色相偏差 <2°）── */
  --color-primary-600: color-mix(in oklch, var(--tidal), black 30%);
  --color-primary-700: color-mix(in oklch, var(--tidal), black 40%);
  --color-primary-800: color-mix(in oklch, var(--tidal), black 50%);
  --color-primary-900: color-mix(in oklch, var(--tidal), black 60%);

  /* success / warning / danger / accent 同構，比例見 §3 */
}
```

### 為什麼 600–900 要用 `oklch` 而不是 `srgb`

| 派生式 | `danger` 暗色步結果 | 色相 |
|---|---|---|
| `color-mix(in srgb, base, var(--ink) 36%)` | `#844C37`（**褐色**） | 39.8° → 漂移 +10° |
| `color-mix(in oklch, base, black 36%)` | `#8F2D00`（深紅橙） | 39.8° → 偏差 0.1° |

黑色在 OKLCH 中彩度為 0，混合時色相由基色決定，因此**完整保留原色相**。

### 為什麼各類別的 black% 不同

因為各基色的明度不同（`primary` L=0.503、`warning` L=0.795），
固定同一百分比會讓淺基色（黃）壓不夠深、深基色（青）壓太深。

**各類別的百分比是為「四個主題同時達標」實測選出的**，見 §3 各表與 §4.3 實測。

## 4. 對比度可達性要求（硬性閘門）

### 4.1 分級門檻

| 等級 | 對象 | 最低比值 | 對應規則 |
|---|---|---|---|
| **A（正文）** | 一般文字、按鈕標籤、表單 label | **4.5:1** | 實體底用 `600` 起；文字用 `neutral-900` 或 `*-700` 起 |
| **AA（大字）** | ≥24px 或 ≥18.66px 粗體 | **3:1** | `*-500` 起 |
| **AAA（圖形）** | 圖表線、icon、邊框、focus ring、狀態點 | **3:1** | `*-500` 起；`neutral-500` 起 |
| **AAA（正文）** | 關鍵文字（可選達標） | **7:1** | `*-700` 起；`neutral-700` 起 |

### 4.2 必須通過的配對組合

```
正文      neutral-900  / neutral-100(--paper)   → 12.10 ✓
次要文字   neutral-600  / neutral-100           →  4.58 ✓
次標題     neutral-700  / neutral-100           →  7.47 ✓（AAA）
連結       primary-600  / neutral-100           → 11.03 ✓
實體按鈕   white        / primary-600           → 11.03 ✓
成功按鈕   white        / success-600           →  7.13 ✓
錯誤按鈕   white        / danger-600            →  6.10 ✓
CTA 按鈕   white        / accent-600            →  6.07 ✓
警告(亮)   neutral-900  / warning-500           →  7.23 ✓
警告(深)   white        / warning-600           →  6.65 ✓
圖形 ≥3:1  primary-500  / neutral-100           →  5.05 ✓
            success-500 / neutral-100           →  3.60 ✓
            danger-500  / neutral-100           →  3.79 ✓
            neutral-500 / neutral-100           →  3.33 ✓
```

#### focus ring 必須用雙層環

**單一顏色不可能同時對「淺底」與「深按鈕」達 3:1**——任一顏色若接近某背景色，
在該背景上必然不足。實測（default 主題）：

| 單一色環 | 對 paper | 對 primary-600 按鈕 |
|---|---|---|
| `warning-500`（亮黃） | 1.67 ✗ | 5.79 ✓ |
| `warning-700`（深） | 8.18 ✓ | 1.18 ✗ |
| `ink` | 12.10 ✓ | 1.25 ✗ |

因此規範強制**雙層環**（WCAG 1.4.11 標準解法），幾何為
`[元件] → 2px 內環 → 2px 外環 → 頁面`：

```css
:root {
  --focus-ring:       2px solid var(--ink);                                /* 外環 */
  --focus-ring-inner: color-mix(in srgb, var(--yellow) 60%, var(--white)); /* 內環 */
}

.app-btn:focus-visible {
  outline: var(--focus-ring);
  outline-offset: 2px;
  box-shadow: 0 0 0 2px var(--focus-ring-inner);   /* 填滿 offset 間隙 = 內環 */
}
```

> **內環為什麼要提亮 40%，而不能直接用 `var(--yellow)`：**
> 四個主題各有自己的 `--yellow`。`exlibris` 的是暗金 `#C99A3D`，
> 對深綠的 `success-600` 只有 **2.77（不達 3）**，此時外環 `ink` 對它也只有 1.75
> —— 兩環都失效。提亮後全域最差 **4.15**，四主題全過。
> 內環的職責本來就是「在深色表面上可辨」，所以**必須偏亮**；
> 淺底那一側由外環 `ink` 負責（10.58–12.46）。

**驗算（判準：每種相鄰背景，兩環取較大者 ≥3:1）**，
`contrast-check.mjs` 檢查 1b 實測四主題 × 四種相鄰面共 16 組：

| 主題 | paper 底 | white 卡面 | primary-600 按鈕 | success-600 按鈕 |
|---|---|---|---|---|
| default | 12.10 ✓ | 13.83 ✓ | 7.53 ✓ | 4.87 ✓ |
| festival | 12.46 ✓ | 13.77 ✓ | 7.68 ✓ | 4.96 ✓ |
| exlibris | 10.58 ✓ | 12.49 ✓ | 6.52 ✓ | **4.15 ✓**（內環） |
| sunny | 12.25 ✓ | 13.24 ✓ | 4.56 ✓ | 4.58 ✓ |

（每一格取 `max(外環, 內環)`；括號標出的是主導的那一環。）

> ⚠ **圖形元素一律用 `*-500` 起**：`*-400` 對 `neutral-100` 只有 2.4–3.3，
> 不達 3:1（`*-400` 僅在純白 `neutral-0` 底上可達 3:1）。

### 4.3 四主題實測（`600` 檔白字）——這是各類別百分比的選定依據

| 類別 | black% | default | festival | exlibris | sunny |
|---|---|---|---|---|---|
| `primary-600` | 30% | **11.08** ✓ | 11.08 ✓ | 11.24 ✓ | **6.25** ✓ |
| `success-600` | 22% | **7.12** ✓ | 7.13 ✓ | 7.13 ✓ | **6.24** ✓ |
| `warning-600` | 40% | **6.66** ✓ | 6.44 ✓ | 8.19 ✓ | **6.07** ✓ |
| `danger-600` | 14% | **6.10** ✓ | 6.10 ✓ | 8.33 ✓ | **6.10** ✓ |
| `accent-600` | 26% | **6.06** ✓ | 6.06 ✓ | 8.48 ✓ | **6.06** ✓ |

## 5. 與現有體系的銜接

### 5.1 新舊 token 對照（零改動遷移）

| 舊 token | 新等值 | 處置 |
|---|---|---|
| `--tidal` | `--color-primary-500` | **保留為別名**（單向綁定） |
| `--tidal-deep` | `--color-primary-700` | 保留為別名 |
| `--coral` | `--color-accent-500` | 保留為別名 |
| `--coral-deep` | `--color-danger-500` | 保留為別名 |
| `--moss` | `--color-success-500` | 保留為別名 |
| `--yellow` | `--color-warning-500` | 保留為別名 |
| `--ink` | `--color-neutral-900` | 保留為別名 |
| `--muted` | `--color-neutral-600` | 保留為別名 |
| `--line` | `--color-neutral-300` | 保留為別名 |
| `--paper` | `--color-neutral-100` | 保留為別名 |
| `--white` | `--color-neutral-0` | 保留為別名 |

```css
/* 定義順序（避免循環）：先定義 --color-*，再把舊名指向新名 */
:root {
  --color-primary-500: /* … */;
  /* … 其餘 --color-* … */
  --tidal: var(--color-primary-500);   /* 舊名 → 新名，單向 */
}
```

既有 **4,496 處 `var(--tidal)` 引用零改動**即生效；新程式碼一律寫 `--color-*`。

> ⚠ **不可**同時寫 `--color-primary-500: var(--tidal)` 與
> `--tidal: var(--color-primary-500)`——會循環。
> （這正是 2026-09-28 色碼收斂腳本曾造成的實際事故，已修復並加驗證。）

### 5.2 與既有四個 token 系列的定位

| 系列 | 職責 | 與本體系關係 |
|---|---|---|
| `--radius-*` | 圓角尺度 | 獨立 |
| `--type-*` | 字級尺度 | 獨立 |
| `--space-*` | 間距尺度 | 獨立 |
| **`--color-*`** | **語意色階（本次）** | 命名與結構與上三者同構 |

### 5.3 主題覆寫只需動基色

```css
:root[data-theme="exlibris"] { --tidal: #4F6B52; --moss: #6C8460; … }
:root[data-theme="sunny"]    { --tidal: #D0932B; --moss: #7A9058; … }
```

色階由 `color-mix()` 派生，**每個主題只需覆寫基色，50–900 自動跟隨**，
無需為四主題各寫一套（≈ 少 160 行重複定義）。

### 5.4 子系統命名空間

`--cr-*`（教室）、`--bx-*`、`--env-*`、`--anime-*`、`--mg-*`：
**保留名稱**，值改為從 `--color-*` 派生（`--cr-sea: var(--color-primary-600)`），
禁止自訂新色相。此為既有規範的延伸，見 `docs/design-tokens.md`。
