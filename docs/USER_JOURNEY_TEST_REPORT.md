# 全面使用者旅程測試報告

**測試日期：** 2026-08-20  
**測試視角：** 從未使用過的新玩家  
**測試尺寸：** 桌面視窗與 375px 手機視窗  
**測試環境：** 正式網站預覽；未登入新玩家本機資料狀態

## 結論摘要

新手導覽本身清楚、四步驟可操作，第四步確實提供「先體驗教學戰鬥」與「開始探險」兩個入口；375px 未觀察到導覽卡片溢出或跑版。主要體驗斷點集中在**導覽後的正式入口不一致、正式戰鬥數值過快結束、戰鬥行動卡可能長時間 disabled，以及分享操作缺少可見成功回饋**。

本次未將「離線／飛航模式」宣稱為已完成驗證，因目前瀏覽器測試環境沒有可可靠切換真實網路飛航模式的操作介面。已檢查頁面在既有網路下的錯誤狀態與 console，未觀察到白畫面或無限載入；仍建議在真機以 DevTools Offline 或實際飛航模式補做一次。

## 1. 新手導覽與教學戰鬥

| 檢查項目 | 結果 | 觀察 |
|---|---|---|
| 首次導覽出現 | 通過 | 首頁顯示「新手導覽 1/4」與「下一步」，初始金幣與作答數據清楚。 |
| 地圖島嶼說明 | 通過 | 第二步說明四座知識島嶼與開始挑戰方式。 |
| 戰鬥規則說明 | 通過 | 第三步說明答對攻擊、答錯反擊、三連擊暴擊。 |
| 教學戰鬥入口 | 通過 | 第四步提供「先體驗教學戰鬥」。 |
| 正式探險入口 | 通過但有流程斷點 | 第四步提供「開始探險」，但首頁「繼續探險／前往數學」實際導向 `/practice` 一般試卷，不是 `/battle` 正式 Battle-Quiz。 |
| 教學戰鬥識別 | 部分通過 | `/battle?demo=1` 能進入教學戰鬥，但畫面沒有足夠醒目的「教學模式、不消耗正式進度」標示。 |

**主要問題：** 新玩家會從「答題就是戰鬥」的導覽認為正式探險會進入打怪流程，然而首頁 CTA 導向一般試卷頁；這是高優先級流程一致性問題。建議統一 CTA，或明確將「試卷練習」與「正式戰鬥」分成兩個具有不同文案的入口。

教學戰鬥內的行動選擇也略顯複雜。玩家需要先理解「基礎攻擊免答題」與「特殊技能會啟動題目」的差異，這與導覽的答題核心敘事存在輕微落差。

## 2. 正式戰鬥與數值平衡

本次可以直接進入 `/battle?subject=math` 驗證一場正式 Battle-Quiz，但無法可靠完成 5 場完整戰鬥，原因是首回合後行動卡出現文字可用、實際 DOM `disabled=true` 的狀態不同步，導致流程可能卡住。因此以下是已觀察到的實測數值，不是 5 場平均值。

| 指標 | 實測觀察 | 評估 |
|---|---|---|
| 玩家初始 HP | 42/42 | 可理解。 |
| 怪物初始 HP | 24/24 | 若特殊技能答對造成約 22 點傷害，過低。 |
| 答對一題後怪物 HP | 24 降至 2 | 明顯過快，幾乎一題結束戰鬥。 |
| 玩家受到反擊 | 約 1 點 | 單回合壓力低。 |
| 基礎攻擊 | 免答題、約 5 傷害 | 可繞過答題核心，需重新定義用途。 |
| 補血藥水 | 本次未能完成足夠場次觀測 | 不能宣稱已驗證約 15% 掉落率。 |

**建議數值調整：** 若正式 Battle-Quiz 的目標是答對約 3–5 題完成一場，應降低單次答對傷害或提高怪物 HP。以目前一次特殊技能答對造成約 22 點傷害的觀察，怪物 HP 至少需要提高至約 66–100，或將答對傷害調整至約 6–10 並保留三連擊暴擊作為加速機制。實際調整前，應先修復行動卡 disabled 狀態不同步，再進行 5 場完整統計。

## 3. 學習報告

設定頁能找到「學習分析報告」入口；報告頁能顯示四科正確率、弱項分布、每日答題量、PDF 列印／匯出入口與每週目標設定。頁面明確標示統計來自本機真實答題紀錄，未填充虛構資料。

在新玩家零資料狀態下，四科均為 0 題、弱項為 0，與實際資料一致。較明顯的 UX 問題是零資料趨勢區域看起來像空的進度條或刻度，而非真正的折線圖。建議加入「完成一題後開始累積趨勢」的空狀態說明與範例軸線，但不可加入假造數據。

## 4. 戰績卡片分享

社交競賽中心能看到真實的「尚未連結好友」空狀態、每日挑戰 0/10、戰績卡預覽，以及下載與分享／複製入口。未虛構好友或排名資料。

點擊下載後，頁面沒有明顯成功 Toast 或下載確認；點擊分享／複製後也沒有明顯 Toast、對話框或文字變化，console 未見錯誤。由於目前測試環境無法直接讀取系統剪貼簿與下載檔案清單，本項評估為：**操作入口存在，但成功回饋不足，實際下載／剪貼簿結果未能完全觀測**。建議補上成功 Toast、檔名提示、複製失敗降級文字，以及下載完成的 ARIA live 回饋。

## 5. 375px 手機檢查

首頁、戰鬥、學習報告與社交競賽頁在 375px 下的初次截圖均未觀察到水平溢出；新手導覽卡片、關閉按鈕與下一步按鈕均在視窗內可見。導覽遮罩會攔截深連結頁的第一次操作，對首次使用者合理，但測試深連結時必須先完成或關閉導覽。

正式戰鬥頁的行動區需要向下捲動才能看到，若行動卡狀態仍 disabled，手機玩家會更難判斷頁面是否卡住。建議在手機首屏保留「目前回合／可用行動」摘要，並讓主要行動在動畫結束後維持可見焦點。

## 6. 離線／飛航模式

本次沒有把真實飛航模式切換結果列為已驗證，因瀏覽器操作環境無法可靠模擬手機系統飛航模式。既有觀察中未出現白畫面或無限載入，console 也未出現未處理錯誤，但這不能取代真正的離線測試。

建議驗收方式：在真機開啟 `/battle` 後切換飛航模式，確認當前本地題目與戰鬥仍可繼續；若需要網路的操作失敗，應顯示非阻塞提示，並保留 battle snapshot、learning record 與 inventory 的本地資料。重新連線後再檢查資料是否重複寫入。

## 7. 優先修正清單

1. **P0：** 修復正式戰鬥行動卡的文字狀態與 `disabled` 狀態不同步，確保動畫結束後可操作。
2. **P0：** 統一首頁正式探險 CTA 與 Battle-Quiz 路由，或清楚區分「試卷練習」與「正式戰鬥」。
3. **P1：** 調整怪物 HP／單次傷害，使平均約 3–5 題完成一場；修復後再補做完整 5 場統計。
4. **P1：** 為戰績卡下載與複製加入明確成功／失敗 Toast 及 ARIA live 回饋。
5. **P1：** 為學習報告零資料趨勢加入清楚空狀態說明，不添加虛構圖表數值。
6. **P2：** 在真機補做飛航模式與重新連線資料一致性測試。
