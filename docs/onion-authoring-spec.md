# 洋蔥學院課程撰寫規格（撰寫動畫課前必讀）

> 這份規格是「撰寫一堂洋蔥學院動畫課」的唯一依據。所有批次、所有學科都適用。
> 課表（要寫哪些課）看 `docs/onion-200-plan.md`；規格（怎麼寫）看本文件。

## 0. 背景

洋蔥學院的動畫課是**資料驅動**的：一堂課就是一份 TypeScript 資料，
裡面同時包含「分鏡字幕」「舞臺教具」「中途提問」「闖關題目」。
動畫播放邏輯完全不用改，新增知識點＝新增一份資料。

產品的核心要求（老師的原話）：**解說步驟要充分且循序漸進、步驟分類要詳細清晰、
視頻圖概念設計要準確無誤**。所以「步驟標籤」與「教具和字幕一致」不是加分項，是硬性要求。

## 1. 檔案與註冊方式

- 一堂課的資料放進 `client/src/game/onion/lessons/<你的檔名>.ts`，**一個批次一個檔**。
- 檔案結構：

```ts
/**
 * <學段><科目>課程（洋蔥學院擴充計畫：<課表章節>）。
 */
import type { OnionLesson } from "@/game/onionAcademyLessons";

const SH_XXX_YYY: OnionLesson = { /* ... */ };

export default [
  SH_XXX_YYY,
  /* ... */
];
```

- **不需要**修改 `onionAcademyLessons.ts`：主檔用 Vite 的 `import.meta.glob` 自動彙總
  `lessons/*.ts` 的 `export default` 陣列（檔名排序即顯示順序）。
- 一個批次只准動**自己那一個檔案**。不要改任何其他檔案（多人同時撰寫，改別人的檔會互相覆蓋）。

## 2. 一堂課的欄位

```ts
{
  id: "sh-phy-newton",        // kebab-case、全站唯一（動手前先 grep 過）
  title: "牛頓運動定律",       // 課名
  subject: "物理",             // 科目
  topic: "力與運動",           // 單元主題
  grade: "高一",               // 年級（依課表）
  stages: ["高中"],            // 只能有一個學段：國小／國中／高中
  desc: "用推車與煞車解釋…",    // 30-50 字課程簡介
  takeaways: ["…", "…", "…"],  // 3 條重點整理（小結頁顯示）
  frames: [ /* 7 幀，見 §3 */ ],
  questions: [ /* 5 題，見 §4 */ ],
}
```

## 3. 分鏡（frames）：一堂課 7 幀

每幀的欄位與規則：

| 欄位 | 規則 |
|---|---|
| `step` | **必須是每幀的第一個屬性**。格式固定為 `步驟 N：<具體動作>`，`N` 等於這一幀的位置（1..7），說明 4-16 個中文字，且**必須描述這一幀真正在做什麼**（不要每堂課都寫「步驟 1：看題目」這種放諸四海皆準的空話）。 |
| `caption` | 20-45 個中文字，對學生說話的語氣（「你看」「我們來」「發現了嗎」）。這一格是老師在講話，要真的在講解。 |
| `action` | `wave`（開場揮手）／`walk`／`point`（指著教具講）／`jump`／`think`（思考）／`cheer`（收尾歡呼）。第 1 幀通常 `wave`、最後一幀通常 `cheer`。 |
| `prop` | 舞臺教具，**必須真的畫得出這一幀的字幕**（見 §5）。 |
| `duration` | 這一幀停留毫秒，2800-4000。內容愈重給愈久。 |
| `ask` | 中途提問，**至少 2 幀**要有（見 §6）。 |

典型 7 幀的節奏（可依學科調整，但要有起承轉合）：

1. 情境引入（生活例子、一個懸問）
2. 把問題講清楚（定義、已知條件）
3-5. 核心推導（每幀推進一個明確步驟）
6. 學生容易搞錯的地方、或換個情境再驗證一次
7. 收斂成口訣／通則，預告闖關

## 4. 闖關題目（questions）：一堂課 5 題

```ts
{
  id: "sh-phy-newton-1",
  prompt: "題幹",
  options: ["甲", "乙", "丙", "丁"],   // 必須 4 個、互不重複
  answer: 2,                            // 正確選項索引（0-based）
  hints: ["第一級提示（指方向）", "第二級提示（更明確但仍不給答案）"],
  explanation: "詳解要說明「為什麼」，不是只重述答案",
}
```

- 順序固定 **2 題基本 → 2 題應用 → 1 題易錯或跨概念**。
- 干擾選項要是**學生真的會犯的錯**（公式代錯、單位沒換、因果顛倒、專有名詞混淆），
  不要放明顯荒謬的選項。
- 詳解要讓「看過動畫的學生」覺得對得上：用動畫裡講過的步驟與說法。

## 5. 教具（OnionProp）與「圖解一致性」硬規則

可用的 `kind`（欄位必須完全照下表，不能自創欄位）：

| kind | 欄位 | 適用 |
|---|---|---|
| `none` | — | 純對白 |
| `text` | `text`, `sub?`, `tone?: "ok"\|"warn"` | 字卡：定義、公式、例句、對照 |
| `bars` | `items: [{label, value}]`, `unit?`, `active?` | 比較數量、統計讀值 |
| `flow` | `steps: string[]`, `active?` | 有先後順序的流程（實驗步驟、反應機構、歷史脈絡） |
| `cycle` | `nodes: string[]`, `active?` | 週期／循環系統（能量流動、板塊循環、生命週期） |
| `numberLine` | `from`, `to`, `marks?: [{at,label?,tone?}]`, `cursor?` | 位置與移動（酸鹼、數線） |
| `balance` | `left`, `right`, `tip?` | 兩邊相等／平衡（方程式、化學反應式配平、供需） |
| `pie` | `a`, `b`, `label?` | 單一分數圓餅 |
| `pies` | `left:{a,b}`, `right:{a,b}`, `result?:{a,b}` | 分數運算過程 |
| `shape` | `shape: "triangle"\|"rect"\|"circle"`, `base`, `height`, `label?` | 幾何（`base`/`height` 必須是 > 0 的數字） |

**圖解一致性（自動檢查，寫錯一定被抓）**：

1. **字幕有數字時，教具必須對得上**。例：字幕寫「甲 20 秒、乙 25 秒」，
   那 `bars` 就必須真的是 20 與 25；不是就報錯。
   → 寫作技巧：**先決定教具的數字，再寫字幕**，字幕一定要把教具上的數字講出來。
2. `bars` 的 `value` 必須 > 0（**畫不出長度 0 的長條**，所以「9:00 → 0 分」這種
   以時刻當數值的寫法是錯的，要改成「經過幾分鐘」）。
3. `pie`／`pies` 的分數要與字幕的分數一致（字幕講 3/4，圓餅就不能是 1/4）。
4. `balance` 的 `left`／`right` 就是字幕在講的那個等式，兩邊都要有數字。
5. `flow.steps` 的順序＝字幕講的順序，且**字幕列舉了幾項就要有幾項**
   （字幕說「三個步驟」，`steps` 就不能只有兩個）。
6. `cycle.nodes` 要與字幕講的循環一致。
7. `shape` 的 `base`／`height` 與字幕提到的尺寸要一致（**且 1-3 這種小數字會被
   當成運算符忽略，所以尺寸請用 4 以上的數字**）。
8. `text.text` 不可以與字幕互相矛盾。

## 6. 中途提問（ask）

- 每堂**至少 2 幀**要有，放在**學生真的會卡住的地方**（不是隨便找兩幀塞）。
- `options` 必須 4 個、互不重複；`answer` 是合法索引；`hint` 是「指方向」而不是給答案。
- 好的位置：公式套用前的判斷、單位換算、方向／正負號、常見迷思的岔路。

## 7. 內容正確性（學科要求）

- 一律使用**臺灣課綱**的用語與慣例（繁體中文、全形運算符 `＋ − × ÷ ＝`、`√`、`≒`、`pH`）。
- 數學：**每一個選項的數值都要自己重算過**。
- 自然／物理／化學／生物：以標準高中教材內容為準，不可杜撰數據或實驗結果。
- 歷史／地理／公民：敘述**中性、有事實依據**；涉及政治的內容只陳述制度與事實，不做價值判斷。
- 英文：寫出的每個句子都必須文法正確、難度符合該年級。
- 人名、年代、地名、單位、符號都要正確。

## 8. 交件前的自我驗證（三項都要做）

```bash
cd <專案根目錄>

# 1) 型別檢查（必須 0 錯誤）
./node_modules/.bin/tsc -p tsconfig.json --noEmit

# 2) 內容體檢（這支腳本會自動讀 lessons/ 目錄，所以你的課一定會被檢查到）
npx tsx scripts/qc-onion-lessons.mts

# 3) 只挑出屬於自己課程的問題（把 <前綴> 換成你的 id 前綴，例如 sh-phy-）
npx tsx scripts/qc-onion-lessons.mts | grep '\[<前綴>'
```

- 體檢輸出最後會列出所有問題，格式是 `[課程 id] 位置：訊息`。
  **屬於你的課的問題必須是 0 個**；別人的課的問題不要動。
- 體檢最後的 `❗ ...課程數應達...` 是**規模門檻**，因為 200 堂還在陸續產出，
  交件時看到是正常的，不用處理。
- 不要刪除或放寬體檢規則來讓自己過關。

## 9. 交件紀律

- **不要 commit**（由主線統一提交）。
- 只新增/修改你自己那一個檔案。
- 回報時列出：你建立的課程 id 清單、`tsc` 結果、屬於你的問題數（必須 0）。
