# 游戏方向调研（2026-09-12）

## 现状盘点

**70 个页面 / 79 个 components / 111 个 game 模块 / 65 个 lib**——代码体量已经超出「小学生学习工具」的规模。

### 现有玩法分类

| 大类 | 入口 | 数量 | 主要数据流 |
|---|---|---|---|
| **酒馆 / 學伴桌** | `/tavern` | 1 个核心页 + 6 个 hotspot 子玩法 | 卡牌收藏 / 金幣 / 學伴 |
| **远征 / 战斗** | `/expedition`, `/battle` | 5+ 个战斗状态 | 卡牌属性 / HP / 难度 |
| **考試 / 答題** | `/practice`, `/wrong-answers` | 4 个核心页 | 知識點 / 錯題归因 / 答題速度 |
| **地图 / 探索** | `/map`, `/camp` | 7+ 页 | 区域 / 知识岛 / 事件 |
| **学习洞察** | `/learning-insights`, `/learning-report` | 5+ 页 | 趋势 / 雷达 / 复盘计划 |
| **教师端** | `/teacher-dashboard` | 1 页 + 4 个子模块 | 班级 / 作业 / 學生排名 |
| **社区 / 对决** | `/community-hub`, `/knowledge-duel` | 2 页 | 排行榜 / 同伴对决 |
| **内容资源** | `/observatory`, `/principles`, `/wisdom`, `/astronomy`, `/safety` | 5 个馆 | 課程標準 / 動態資料 |
| **獎勵 / 收集** | `/badges`, `/card-collection` | 2 页 | 稱號 / 卡牌圖鑑 |

**核心循环**（已实现）：
```
答題賺金幣 → 酒館消費（卡包 / 學伴） → 卡牌投入戰鬥/远征 → 錯誤知識點回炉
```

## 现有循环的 4 个真实问题

1. **酒館消費缺乏長期目標**——金幣越攒越多但没有"花掉"的紧迫感
2. **戰鬥/远征 缺少跨頁聯動**——玩完一個再進另一個，狀態不傳遞
3. **AI 學伴仅作 on-demand 工具**——沒主動派任务（错题學習是被動的）
4. **同班 2 學生間缺少協作/競爭**——1 老師 2 學生場景下沒差異化玩法

## 4 个可落地方向

### 方向 A：**跨页面赛季 / 活动系統**（推荐优先）

**一句话**：每月/季一个限时主题（比如「潮汐尋寶」「星空觀測」），把现有 4-5 个玩法串起来。

**示例**：本月主题「潮汐尋寶」
- 答題 → 獲得「貝殼碎片」（新道具）
- 每天 3 個碎片可兌換 1 次「潮汐骰子」
- 骰子決定远征地圖上多走 1-3 步
- 走到限定區域解鎖限定卡牌 / 稱號
- 月底結算：累積貝殼數 → 學期榮譽

**技術復雜度**：**低**
- 新增 `season_event` 數據表（cloudsave 已有架構可復用）
- UI：1 個新組件（賽季 banner）+ 4-5 個現有頁面加 tab/徽章
- 不需新 LLM 调用

**现有架構契合度**：★★★★★
- 卡牌、金幣、稱號、知識島現成
- 唯一新東西：時間限定的「主題/碎片」變量

**與 AI 學伴聯動**：賽季中學伴可主动推送「今天再答 5 題拿 3 碎片」

**收益评估**：
- 留存：每天登錄有具体目標（金幣 → 碎片，主題性更強）
- 學習：跨玩法的「解鎖感」讓答題更積極
- 商業：未来可加付費賽季通行證

---

### 方向 B：**学习任务链 / Streak 任务鏈**

**一句话**：把現有「每日簽到 / 答題 / 錯題复練 / 远征」包裝成一條串連的每日任務链。

**示例**：
```
每日三步任务：
  ☑ 签到（已完成）
  ☐ 答 5 题数學（已完成 3/5）
  ☐ 重練昨天錯題 2 道（未完成）

完成度影響：
  - 3/3 → 雙倍金幣 + 限定卡背
  - 1-2/3 → 正常金幣
  - 0/3 → 學伴桌主動關心（AI 學伴對話）
```

**技術復雜度**：**中**
- 新增 `daily_task_progress` 表（userId / date / step / status）
- UI：1 個新組件（任務面板 toast/banner）+ 學伴桌整合
- AI 學伴的「0/3 主動關心」需要新增 LLM 調用点（任务提醒 prompt）

**现有架構契合度**：★★★★☆
- dailySignIn.ts 已有現成邏輯可擴展
- tRPC teacher/student 已有進度查詢

**與 AI 學伴聯動**：0/3 触發學伴對話（已有 `aiTutor.explain` 端點可擴展）

**收益评估**：
- 留存：連續 7 天獎勵加大 → 連續登錄
- 學習：主動重練錯題 → 薄弱點覆蓋
- 心理：學伴關心是「正向激勵」不是「責備」

---

### 方向 C：**AI 學伴主動委派任務**

**一句话**：讓 AI 學伴（基於錯題分析）主動给学生派任务，而不是「學生錯了才出 AI 提示」。

**示例**：
- 學生錯了「面積換算」3 次
- AI 學伴在學伴桌提示：「我們今天再練 2 題面積好不好？」
- 學生同意 → 自動從備用題庫拉同知識點 5 題
- 完成 → 學伴桌回應鼓勵 + 知識點雷達更新

**技術復雜度**：**中-高**
- 需要新的 `aiTutor.delegateTask` 端點（基於學生錯題生成任務）
- 需要 `targetedPractice` 與 `errorAnalytics` 整合（兩者已存在但獨立）
- UI：學伴桌對話流程改造（不是按鈕式點开，而是 ChatFlow）

**现有架構契合度**：★★★★☆
- `aiTutor.reviewPlan` 已有類似能力（錯題→複習計畫）
- `targetedPractice` 已有備用題庫
- `errorAnalytics.ts` 已有錯誤归因
- 缺：把三者串成一個主動流程

**與 AI 學伴聯動**：**這就是 AI 學伴的核心**

**收益评估**：
- 學習：錯誤薄弱點主動覆蓋（不是學生自己想起要複習）
- 情感：學伴「記得你的薄弱点」是強情感連結
- 商業：AI 訂閱的差异化卖点

---

### 方向 D：**同伴协作 / 競爭模式**

**一句话**：让 1 老师 2 學生場景下兩個学生有具体互动玩法。

**示例**：
- **協作**：每週一個「雙人任务」——兩個學生各解一半卡牌，組隊打一個強敵
- **競爭**：每週排行（按答題速度 / 正確率 / 卡牌強度），前三名限定稱號
- **協作 + AI 學伴**：兩個學伴對話可「請教」（學伴 A 推荐給學伴 B 一起做）

**技術復雜度**：**中-高**
- 新增 `class_partnership` / `weekly_competition` 表
- 即時通訊（如兩人協作）需 WebSocket 或 polling
- 老師端控制：協作還是競爭？老師設定？

**现有架構契合度**：★★★☆☆
- `community-hub` 有基礎社群架構
- `knowledge-duel` 已有 1v1 對戰
- 缺：長期合作机制 / 班級級任務

**與 AI 學伴聯動**：學伴桌可作為「兩人對話的中介」

**收益评估**：
- 留存：社交元素 > 單機學習
- 教學：老師可控（協作 vs 競爭 vs 個別化）
- 風險：兩個學生進度差距大時，競爭可能打擊落後者

---

## 推荐路线

| 顺序 | 方向 | 预计工作量 | 依赖 |
|---|---|---|---|
| 1 | **C**（AI 學伴主動委派） | 1-2 周 | 擴展 `aiTutor.reviewPlan` + 整合 `errorAnalytics` + 學伴桌 ChatFlow |
| 2 | **B**（Streak 任务鏈） | 3-5 天 | 擴展 `dailySignIn` + AI 學伴提示 |
| 3 | **A**（跨頁賽季） | 1 周 | 新增 season 表 + banner UI |
| 4 | **D**（同伴協作） | 2-3 周 | WebSocket + class_partnership 表 |

**理由**：C 是「AI 學伴大脑」自然延伸（用户已投入多 provider LLM 链路的成本），B 是 C 的辅助（任務完成度可触发學伴主動關心），A 是把現有玩法「主題化」包裝、D 是社交層增量。

## 不建议的方向

- ❌ **新增更多独立 mini-game**：現有 70 個頁面已過載，再加新模組只會讓老師/學生更迷茫
- ❌ **遊戲化加深（如寵物進化、卡牌稀有度系統）**：會讓「學習」變「氪金」本末倒置
- ❌ **實時對戰 / 排名刷榜**：1 老师 2 學生場景下沒有對手，刷榜變成「自己跟自己的影子比」

## 擴展方向（第二批：補 A-D 沒覆蓋的維度）

### 方向 E：**間隔重复 / Spaced Repetition（艾賓浩斯遺忘曲線）**

**一句话**：按遺忘曲線自動排程錯題复練時間，不是「错過當天就忘」，而是「1 天後、3 天後、7 天後、14 天後」按曲線復现。

**示例**：
- 學生錯了「面積公式」題 → 1 天後自動推一道同知識點變體
- 答對 → 推到 3 天後；答錯 → 重置間隔
- 學生打開首頁，「今日複習」顯示「3 道待複習」（不堆積不焦慮）
- 完成率達 100% 解鎖「記憶大师」稱號

**技術複雜度**：**中**
- 新增 `review_schedule` 表（questionId / nextReview / interval / status）
- 改 `errorAnalytics` 觸發排程（錯題時插入新行）
- UI：首頁 +1 個「待複習」入口 + 错題重练頁加「遺忘曲線」圖

**现有架構契合度**：★★★★★
- `targetedPractice` 已有備用題庫可挑變體
- `errorAnalytics.ts` 已記錯題
- `aiTutor.explain` 可作複習引導

**與 AI 學伴聯動**：AI 學伴可解釋為什麼這道題該今天複習（強化主動性）

**收益评估**：
- 學習：**長時記憶率提升 2-3 倍**（認知科學有大量證據）
- 留存：每天都「有事做」但不重複
- 商業：對補習班 / 家長有強付費意願（背單詞 app 都靠這吃飯）

---

### 方向 F：**知识图谱 / 学习路径可视化**

**一句话**：把現有「知識島 / 區域 / 點位」升级为有向連接的图譜，學生能看到「我學過的節點與未解鎖節點的關係」。

**示例**：
- 視覺化：圓圈是知識點，線是「先決條件」（學「加法」才能學「乘法」）
- 學生當前進度：高亮已掌握 / 灰色未解鎖 / 紅色薄弱點
- 點擊某節點：彈出該知識點所有錯題 + 學伴建議
- 老師端：全班同學的图譜疊加圖，找共通薄弱節點

**技術複雜度**：**中-高**
- 新增 `knowledge_graph` 表（knowledgeId / prerequisites / difficulty）
- UI：1 個核心 graph 渲染組件（推薦 `react-force-graph` 或自寫 SVG）
- 設計：圖譜布局算法（避免 200 個節點擠一起）

**现有架構契合度**：★★★☆☆
- `/map` 已有區域概念但不是 graph
- `client/src/data/` 可能有 knowledge taxonomy
- 缺：實際圖譜數據結構與算法

**與 AI 學伴聯動**：點擊薄弱點 → 學伴主動派練習（與 C 互補）

**收益评估**：
- 留存：「地圖感」是強情感連結（像 RPG 開放世界）
- 學習：把碎片知識連起來，強化理解
- 教學：老師能看到「這個學生跳過了先決條件」這類盲點

---

### 方向 G：**家长门户 / 亲子共学**

**一句话**：家长不只是看進度，被動接收週報，而是能**主動参与**——設定每日目標、發送鼓勵卡、共學关卡。

**示例**：
- 家長登入 `/parent` 看孩子本週答題、错題分布、學伴建議
- 可設「今天目標：數學 5 題」（影響孩子首頁目標提示）
- 可發「鼓勵卡」——一句話 + 一個 emoji，孩子學伴桌會顯示「媽媽今天說：加油！」
- 共學关卡：週末家長和孩子各答一半題，組隊過關

**技術複雜度**：**中**
- 新增 `parent_account` / `encouragement_card` 表
- UI：1 個家長端頁面 + 學生端 1 個鼓勵卡彈窗
- 認證：家長用 email 註冊，學生端綁定（老師批准）

**现有架構契合度**：★★★☆☆
- 老師端有 email 概念但無家長
- `cloud_saves` 已有名字鍵，可擴展關係
- 缺：家長獨立認證系統

**與 AI 學伴聯動**：家長和學伴可同時鼓勵（「學伴」+「媽媽」雙重正向反饋）

**收益评估**：
- 留存：家長是「付費決策者」，拉到家長就拉到家長的錢包
- 學習：家長參與是學生最大的學習動機（教育心理學共識）
- **商業**：家長訂閱 / 升級版的天然收費對象

---

### 方向 H：**多模态学习 / 语音答题**

**一句话**：低年級或閱讀障礙學生可用語音答題，圖像題取代純文字題。

**示例**：
- 語音答題：「小華有多少蘋果？」→ 學生說「5 個」→ STT 識別 → 判對錯
- 圖像題：數學題不再是「3 + 5 = ?」而是顯示 3 個蘋果 + 5 個蘋果的圖片讓學生圈答案
- 触覺/手寫：學生在屏幕上畫 / 寫答案（適合低年級或特殊需求）
- TTS 朗讀題目：現有 `tts.synthesize` 端點可復用

**技術複雜度**：**中-高**
- 圖像題：題庫要擴展（題目要帶 SVG / 圖片 url）
- STT 識別：學生說話→文字（Edge TTS / Web Speech API / Whisper）
- 評分：語音答案要比對預期（容錯匹配：「5 個」「五個」「伍」都算對）

**现有架構契合度**：★★★☆☆
- `tts.synthesize` 已就位（Edge TTS）
- `client/src/lib/speechSynthesis` 已有語音播放
- 缺：STT（語音轉文字）+ 圖像題存儲 + 模糊匹配

**與 AI 學伴聯動**：學伴桌可語音對話（學生說話，學伴語音回）

**收益评估**：
- 學習：低年級 / 閱讀障礙 / 不識字也能用（**普惠價值**）
- 留存：語音互動的「自然感」比純文字更強
- 商業：海外市場（不會中文 / 英文輸入慢的用戶）天然契合

## 推荐路线（含 E-H 重排）

| 顺序 | 方向 | 预计工作量 | 依赖 |
|---|---|---|---|
| 1 | **C**（AI 學伴主動委派） | 1-2 周 | 擴展 `aiTutor.reviewPlan` + 整合 `errorAnalytics` + 學伴桌 ChatFlow |
| 2 | **E**（間隔重复） | 1 周 | 新增 `review_schedule` 表 + 改造 `errorAnalytics` |
| 3 | **B**（Streak 任务鏈） | 3-5 天 | 擴展 `dailySignIn` + AI 學伴提示 |
| 4 | **A**（跨頁賽季） | 1 周 | 新增 season 表 + banner UI |
| 5 | **F**（知識图譜） | 1-2 周 | 新增 `knowledge_graph` 表 + graph 渲染組件 |
| 6 | **G**（家長門戶） | 1 周 | 新增 `parent_account` 表 + 認證系統 |
| 7 | **D**（同伴協作） | 2-3 周 | WebSocket + class_partnership 表 |
| 8 | **H**（多模態） | 2-3 周 | STT + 圖像題 + 模糊匹配 |

**理由**：
- **C+E 是強協同**：AI 學伴主動委派的「什麼時候练」由間隔重複算法決定
- **B 是 C 的日常化**：任務完成度觸發學伴主動關心
- **A 是包裝層**：把 C+E+B 包成一個「賽季主題」
- **F 是長期願景**：知識图譜展示「你學到哪了」給所有方向提供視覺錨點
- **G 是商業化跳板**：拉到付費決策者
- **D+H 是長尾**：社交與無障礙

## 数据驱动的决策依据

当前 server 数据表（`server/db.ts`）已經有：
- `cloud_saves` / `exam_records`（学生进度）
- `class_rooms` / `class_members`（班级）
- `assignments` / `submissions`（作业）
- `collections`（卡牌）

**新功能不需要重新建模**——只要加 1-2 张关联表即可。
