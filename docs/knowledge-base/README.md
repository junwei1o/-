# 知識庫

這裡是**給站長、給之後的 agent（包括我自己）** 看的專案知識。

## 為什麼這些內容要放進站內

同一份知識有三種讀者，如果各自有一份，遲早會不一致：

1. **站長** —— 在瀏覽器的 `/admin` 讀
2. **之後的 agent** —— 在本機讀檔、grep、修改
3. **站長自己** —— 用任何編輯器看這個 repo

所以這裡的 markdown 是**唯一真實來源**，後台只是把它讀出來顯示。
改了這裡，站長下次打開後台就看到；agent 下次讀檔也看到——**不需要改任何程式碼**。

## 寫這份文件的三條規則

1. **只寫真的。** 每個數字、每個路徑、每個結論都要能對回 git 歷史、程式碼或實測。
   拿不確定的就寫「不確定」，不要編。
2. **寫「為什麼」不只寫「是什麼」。** 程式碼已經記錄了「是什麼」，
   沒有記錄、也最容易失傳的是「當初為什麼選這個做法」。
3. **踩坑要寫清症狀。** 只寫結論沒用——下次卡住時，人是先看到症狀才會想起這份文件。

## 維護方式

- 新增一份文件：在 `docs/knowledge-base/` 放一個 `.md` 即可，後台會自動收進清單。
- 檔名以數字開頭可控制排序；`_` 開頭的檔案不會上架（暫存用）。
- 單檔上限 160 KB，寫太長代表該拆。
