# 註釋與文案慣例（comment-conventions.md）

> **用途**：本專案的註釋、括號補充、用字規則。**只寫規則，不改既有程式碼**——
> 「全庫補英文中文釋義」是獨立任務，不在此文件的落地範圍。
>
> 本檔為**活文件**；最後更新：2026-10-07。

---

## 1. 英文術語的中文釋義

**分層規則**（避免「全庫補中文」變成噪音）：

| 類型 | 處理 | 例 |
|---|---|---|
| **專案內通用術語**（首次出現於某檔案時） | 加中文釋義 | `lazy-load（延遲載入）`、`tree-shaking（搖樹最佳化）` |
| **業界通用且國小教師也懂** | **不加** | `token`、`cache`、`API`、`props` |
| **識別符／檔名／指令／旗標** | **不加** | `useQuestionBank`、`index.html`、`--pool=forks`、`runtime_bank` |
| **已有既定中文譯名且全站一致** | 用中文，不夾英文 | 「題庫」而非 `question bank` |

**判準**：加中文是為了**降低讀者查詢成本**，不是為了顯得完整。
若讀者（含未來的 agent）看到該英文會卡住 → 加；不會卡 → 不加。

## 2. 註釋裡的數字（三類角色）

> 本專案曾因註釋數字漂移付出代價（2900 題、3MB、2.7MB 等，詳見
> `~/1zz/數字與註解漂移_方法論_20261007.md` 與 `handover-errata.md`）。

| 角色 | 判據 | 處理 |
|---|---|---|
| **守衛閾值** | 數字錯了會導致錯誤行為或回歸 | 保留精確 ＋ **指向權威來源** |
| **驗證錨點** | 用於比對、測試、grep | 保留精確 |
| **解釋性裝飾** | 只是讓描述「有份量」 | **若無語意功能則刪** |

**核心判據**：把數字刪掉，這句話還成立嗎？
- 「題庫 **2.7MB** 採動態載入」→ 成立 → 裝飾，刪
- 「下載題庫（**344KB gzip**），不跟首屏搶頻寬」→ 刪後失去量級對比 → 保留

⚠️ 不是「裝飾一律刪」，是「**裝飾若無語意功能則刪**」。

## 3. 註釋該解釋什麼

- **解釋「為什麼」與「為什麼不能那樣做」**，不是「這是什麼」。
  - ✅ `// ⚠️ 勿把 Home 改回靜態 import：AuthGate 未登入只渲染 LoginPage，靜態 import 會讓題庫 chunk 進登入頁首包`
  - ❌ `// 這是首頁元件`
- **守衛型註釋要寫「違反的後果」**，否則後人不知為何不能改。
- **解釋「為什麼可以是任何值」比「這不是什麼」更有用**：
  - ✅ `// mock 值：測 AdminConsole 如何渲染後端回傳的數字，與真實題庫規模無關`
  - ❌ `// ⚠️ 以下皆為 mock 值，非真實題數`
- **能從源頭消除歧義時，別用註解**：測試 mock 值用明顯假數字（`9999`）勝過加註解說明。

## 4. 事實陳述的權威來源

- 精確數字**寫在權威來源處**，註釋不複寫。
  - 題數 → `data/runtime_bank_elementary.json`
  - 測試規模 → `npx vitest run`
  - 版本 → `package.json`
- 註釋若必須提數字，**附「量測日期 + 指令」**，否則它會在無人察覺時過期。

## 5. 每輪開工前的檢查（與 `handover.md` 並行風險節互補）

1. `git fetch origin && git log HEAD..origin/main --oneline`——同步上游
2. `git log @{u}..HEAD --oneline`——**檢查本地有無他人的未推送 commit**
3. 共用文檔（`handover.md`、`handover-errata.md`、記憶檔、`~/1zz`）編輯失敗時**先重讀現文再改**

> 本 clone 為**共享工作副本**（多 writer、作者身份不可辨），故 commit message 應標明來源（如 `[agent-X]`）。

## 6. 編輯後的驗證（多節文件必做）

**病灶**：對「含多個 `##` 章節」的文件做 `edit` 時，若 `old_string` 跨越章節邊界，
很容易**吃掉下一個章節標題**，使表格變成無標題孤表——而 `edit` 成功回報不會提示這件事。

**實例（2026-10-07）**：在 `handover-errata.md` 的「未解風險」節前插入「待辦」節時，
`old_string` 用了 `## 未解風險（非勘誤，為待觀察項）` 作為錨點並替換掉，
導致該標題消失、R-01/R-02 表格成為無標題孤表。**當場 `grep` 結構才發現。**

**規則**：多節文件每次 `edit` 後，**跑一次結構檢查**：

```bash
grep -n "^## " <file>          # 章節清單——數量與名稱是否與編輯前一致
awk '/^## /{if(prev&&!c)print "空節: "prev; prev=$0; c=0; next} /^\|/{c=1}' <file>
```

- 期望：**章節數不變**（除非本來就要增刪章節）
- 若少了一節 → 檢查 `old_string` 是否誤含標題

**另一條**：凡**改寫過的技術字串**（指令、路徑、hash、版本號），改完**逐字重讀**該段——
`edit` 只保證字串替換成功，不保證語義與結構完整。
