# 評估報告 5b：生成器版本對齊可行性（A 方案是否值得重啟）

**日期**：2026-10-18｜**狀態**：評估完成
**結論：不值得對齊；維持 B（覆蓋守門）。A（append-only）永久不做。**

## 一、先確認 E2g 的性質（實測，非推論）

| 判準 | 實測結果 | 意義 |
|---|---|---|
| 確定性 | 同 seed 連跑兩次**逐字元相同**（3886 題） | 生成器**沒有不確定性** |
| 非確定性來源掃描 | `Math.random` 0 處、`Date.now`（生成邏輯）0 處、`readdir` 0 處 | 排除了亂數與目錄順序 |
| 我方 commit 的貢獻 | sed 關掉三個 formula 守門後重跑**同為 3886** | `10340ea` 對落差貢獻＝0 |
| 決定性旁證 | 腳本寫檔帶尾換行、committed 檔尾無換行 | committed 檔**非現行腳本產出** |

**結論**：3966 vs 3886 是**版本漂移**，不是 bug、不是非確定性。
（E2g 條目中「多次不同版本生成器累加」的說法過於籠統，已被本次實測收斂。）

## 二、對齊成本量化

### 現況結構

```
生成器改動 commit：10 次
資料檔改動 commit：16 次        ← 資料被獨立改動的次數 > 生成器
```

### 關鍵障礙：RNG 流不可逆

生成器使用**單一 RNG 流**（`rng = mulberry32(SEED)`），依序餵給：

1. `generateMatchingRelations(rng, collector, 170)`
2. `generateCrossSubject(rng, collector, 200)`
3. `generateMath` / `generateFromFacts` × 5 科

任何一步驟的**增／刪／改**，都會讓後續所有題目的亂數序列偏移，題目全變。

因此「對齊」的本質是：**找出一個精確的歷史 generator 版本**，
使它重跑後恰好產出 committed 的那 3966 題。

### 為什麼做不到

1. **找不到那個版本**：committed 檔的 `generatedAt` 顯示它是
   2026-09-20 的單次產出，但那之後生成器經歷 9 次實質改動
   （跨科結合題新增、國中內容移除、formula 守門…），每一個都改動 RNG 流。
2. **即使找到也回不過去**：回退 generator 會同時丟失之後所有
   事實表更新與跨科題邏輯——而那些是**有價值的改進**，不該為了
   對齊一個舊快照而丟棄。
3. **有不可再生的成分**：`deepReasoning.mjs` 存在，但
   `expand-question-bank.mjs` **沒有 import 它**；深思題 200 題
   是在 `1661d89` 以其他方式進入資料檔的。這部分無法用現行 generator 再造。

### 若硬要做的成本

| 步驟 | 內容 | 估計 |
|---|---|---|
| 1 | 找出 2026-09-20 的 generator 版本 | 需遍歷 9 次 generator diff 逐一試跑比對 |
| 2 | 確認該版本能重現 3966 | 可能仍否（RNG 流受 `SEED` 與呼叫順序雙重約束） |
| 3 | 把後來 9 次改動「移植」回舊版 | 每次改動都會再動 RNG 流 → **無限回歸** |

**第 3 步是死路**：任何移植都改動 RNG 流，等於要對齊一個移動的目標。

## 三、結論：永久放棄 A（append-only），保留 B（覆蓋守門）

### 理由

1. **A 的前提不成立**。append-only 的價值在於「重跑是無損的」。
   但這個專案的重跑**永遠是全量重建**（RNG 流設計使然），
   A 只能給出「一次追加 2407 題、其中 227 題重複、下游 bundle 爆到 3.1MB」
   的結果——它是**用另一種方式製造問題**，不是解決問題。
2. **對齊成本無限**（第 3 步的回歸問題）。
3. **B 已經完整解決原始問題**。E2g 的真實危害是
   「盲信 note 重跑會靜默弄丟 2487 題」。B 從根上堵住了它：
   寫入前比對、漂移／刪除分類報錯、CI 題庫規模閘門兜底、
   runbook 明文規定。危害已消除，無須再談 A。
4. **維護成本對比**。B 是一次性、可理解、已被失效注入驗證的機制。
   A 需要一個不存在的「可重現 generator」作為前提。

### 已採取的替代措施（皆已實作並驗證）

| 措施 | 作用 |
|---|---|
| `expand-question-bank.mjs` 寫入前守門 | 漂移／刪除分類報錯，拒絕寫入 |
| `--dry-run` / `--force-overwrite` / `--seed` / `--quiet` | 讓「看清楚再動」成為可能 |
| `qc-bank-count.mjs`（CI 第九道） | 題數下降即 fail，兜底 |
| `verify-generator-determinism.mjs` | 三判準（確定性／可重現／覆蓋危險），可重跑 |
| runbook（03 新增 5 條規則） | 明文規定「個別修題直接改資料」 |

## 四、未來若要讓 generator 真正可用（不屬本次範圍）

若站長日後確實需要「全量重生」，**唯一可行路徑**是：
讓生成器成為**唯一真相**，然後接受一次性的內容重置——
把所有人工累積的題目（含深思題 200、跨科結合題）收進生成器的事實表，
再重生一次，並用 `qc-bank-count` + 審計腳本確認品質。

這是一次**明確的內容重置決策**，不是技術債修補，需站長裁示。
